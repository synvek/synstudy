# Open-Core + 买断制 Pro 详解

## 一、概念拆解

这是两个独立模式的组合：

**Open-Core（开源核心）**：软件的"核心部分"开源（GPL/MIT 等），围绕核心之上的"增值部分"闭源收费。与"全闭源"或"全开源"都不同——它承认开源的价值（获客、信任、社区贡献），同时保留一块商业空间。

**买断制（Lifetime License）**：用户**一次性付费**获得 Pro 功能的永久使用权，没有订阅、没有月费。与 SaaS 订阅相对。

组合起来就是：**免费版永远免费且开源，Pro 版是一次付费的功能解锁包，付费的是"功能"而不是"数据"或"时间"。**

---

## 二、为什么这个组合特别适合 synstudy

回顾上次分析的三个约束，这个模式逐一化解：

| synstudy 的约束 | Open-Core 买断制的应对 |
| --- | --- |
| 词典数据全是开放许可（CC-BY-SA 还要求演绎数据共享），**数据卖不了** | 只卖代码层功能，`synstudy.db` 随免费版公开，合规无冲突 |
| **纯离线、无后端**，做不了订阅校验 | 买断制用**离线 license key** 即可校验，零服务器成本 |
| **GPL-3.0 词表传染风险** | 核心开源反而免疫——代码本来就开源，只需替换数据源；Pro 部分不含 PEP 词表即可 |
| 桌面用户画像：开发者、极客为主，**反感订阅、接受买断** | 一次付费 ¥30–68，恰好匹配这个人群的心理账户 |
| Rust + Dioxus 单代码库 | Free/Pro **共用同一个二进制**，一个 feature flag 区分，维护成本极低 |

## 三、具体怎么切分 Free / Pro 边界

这是模式成败的关键。切分原则：

> **免费版必须"完整且慷慨"，Pro 版卖的是"更好"，不是"残废后赎回"。**

背单词工具被订阅制玩坏了口碑（不复习就锁词、云同步收费），Open-Core 恰恰是反着做——把"良心开源工具"本身当营销。

### 免费版（开源，MIT/Apache-2.0）
维持现状的全部核心功能：
- 双向词典查询、9 大分级词库
- 学习模式、SRS 背诵/复习、进度统计
- 三个测验题型（选词填空/句意选择/听音辨词）
- 数据文件 `synstudy.db` 构建管线（`scripts/`）也一并开源

### Pro 版（闭源，一次买断）——加料不加底座
按"实现成本从低到高"排：

1. **词根词缀学习视图**（路线图已有 `wordroot.txt` 预留）
   - `word_roots` 表 + 按词根聚合的批量学习页："记住 spect = 看，一词串起 inspect/prospect/perspective…"
   - 数据来自 MIT 的 ECDICT，加工逻辑是专有代码 → **卖功能不卖数据，CC-BY-SA 不触发** ✅
2. **打字练习模式**（借鉴 qwerty-learner 交互，但用自己的实现）
   - 键盘实时击键校验 + 拼写错误热力分析，桌面键盘场景是移动端的天然差异化
3. **计划包（Plan Packs）**
   - "托福 30 天冲刺""四级考前 21 天"等预设轮次计划模板（项目已有轮次表结构，直接复用）
   - 卖的是**编排方法论**，不是词汇数据
4. **深度统计**：遗忘曲线预测、每日复习量长期趋势、词库掌握度雷达图
5. **外观与效率**：主题、自定义快捷键、 vim/emacs 式工作流
6. **数据互通**：Anki 双向导入导出、进度备份到自定义路径

### 明确不放进 Pro 的（红线）
- ❌ 现有的任何免费功能不降级、不移除
- ❌ 词典数据本身不收费（CC-BY-SA Share-Alike 义务）
- ❌ 不设"激活次数上限""换机需联系客服"这类惩罚性 DRM——桌面买断用户最恨这个

## 四、技术与发行架构

```
synstudy 单仓库
├── src/                      # 开源核心（Free = Pro 的底座）
│   └── ...
├── pro/                      # 私有仓库或 workspace 成员（闭源）
│   ├── word_roots.rs         # 词根视图
│   ├── typing_mode.rs        # 打字练习
│   └── license.rs            # key 校验
├── Cargo.toml
│   features = ["pro"]        # cargo feature 控制编译
```

两种实现路线，成本不同：

| 路线 | 做法 | 优缺点 |
| --- | --- | --- |
| **A. Feature flag 双构建**（推荐起步） | 开源仓库只有 free feature；Pro 代码在私有 repo，打 bundle 时合并编译出 Pro 版二进制 | 简单干净；缺点是要维护两个发布产物 |
| **B. 单二进制 + 解锁** | 一个安装包，输入 license key 后 Pro 模块激活 | 用户换机重装方便；但 Pro 代码实际在二进制里，可能被逆向——桌面软件通常也就防君子 |

**License key 的离线校验**（无后端的关键）：
- 用 Ed25519 非对称签名：你在私钥侧签发 `用户名|设备指纹|到期策略` 的 key，应用内嵌公钥验签
- 全程离线完成，零服务器；签发可以走"付款后邮件发码"或接入 Lemon Squeezy / 爱发电的 webhook（这是唯一可选联网点）
- 激活次数想限制就在 key 里编入设备指纹绑定，第一轮买断不必做严

## 五、账怎么算——收入预期要现实

买断制 + 无后端，意味着这是**"小钱但利润率高"**的生意：

```
收入 = 下载量 × 付费转化率 × 客单价 × 购买人数占比

参考值（桌面效率工具品类经验）：
- 开源工具付费转化率：0.5%–3%
- 合理定价：¥38–68（对标 Dash 约 $10、TablePlus 买断等）
- 服务器成本：≈ 0（无后端）
- 支付抽成：Lemon Squeezy ~5% / 爱发电 ~10%
```

乐观情形：做出 1 万次下载（靠 Reddit/V2EX/即刻的"良心开源背单词工具"传播），3% 转化 × ¥48 ≈ **¥1.4 万/波**，买断制的遗憾是长尾衰减快（一次购买后没有复购），除非有新 Pro 模块可更新——这反过来要求你**持续产出 Pro 功能来刺激存量用户推荐新用户**。

所以它的定位应该是：**养活项目、验证付费意愿的第一步**，而不是终点。天花板仍在移动订阅与机构授权（上次分析的阶段三）。

## 六、实施路线图

```
第 0 步（前置，1–2 周）
  排除许可雷：剔除 qwerty-learner GPL 词表（换官方大纲）、
  替换 kajweb 专四/专八来源 → 否则开源版本身都不宜对外分发

第 1 步（建立信任池，持续）
  开源 Free 版发布：GitHub + Homebrew Cask + Microsoft Store（免费版）
  目标：先有 1000 个 star 和真实使用反馈，没用户谈付费是空的

第 2 步（验证付费，4–6 周开发）
  Pro 三件套：词根视图 + 打字练习 + 一个计划包
  Lemon Squeezy / 爱发电收款 → 邮件发码 → 应用内输码解锁
  在 GitHub 仓库显著标注 Open-Core 分界，避免社区反弹

第 3 步（扩大战果）
  Pro 模块按月/季度节奏上新（错词本强化、深度统计、主题）
  攒够付费用户证据后，再启动 Web/移动订阅的融资级路线
```

## 七、一句话总结

对 synstudy 而言，Open-Core 买断制 = **把"数据不能卖、架构没后端、用户是极客"这三个约束直接变成设计依据**：开源核心换信任和分发，闭源 Pro 卖离线功能加工层（词根视图、打字练习、计划包），用签名 license key 做零服务器校验。它不是最赚钱的模式，但它是这个项目**当前形态下变现路径最短、合规风险最低、社区口碑代价最小**的第一步——真正的长期收入留给移动订阅和机构授权。
